## 鸣潮：实际契约缺陷修复与复验

真实角色接口返回明确的 `{schema_version, role_id, server_id, character_id, data, provenance}` 包装。外层 `role_id` 是账号身份，内层 `data.role.role_id` 才是游戏角色。网页已正确消费 `data`，评分归档选择遗漏此层，导致有装备却返回零件。

新增共享解包函数只接受版本 1 明确包装，并检查外层 `character_id` 与内层角色 ID 一致；兼容明确的旧平面数据，不递归猜测其他包装。账号/区服仍由原归档范围过滤，账号 ID 不作为角色 ID、不进入图片。装备、评分投影和共享截图使用同一校验，选中归档保留自己的观测时间。

相关回归 **108 passed、8 skipped**（这组命令未配置浏览器环境），2 个已有弃用警告。新增匿名响应形状用例先失败再通过；没有把合成数据作为真实账号证据。

修复后再次对同一目标角色做一次实时详情读取，再读取本地装备适配结果：两者均 HTTP 200，身份校验通过；**5 件声骸、35 条词条（25 个百分数项、10 个平值项）**，物品标识及每条词条的值、单位、属性 ID、观察标识和主副项均在内存中逐项比较一致。未配置权重仍 `unconfigured`、分数为空，完整性仍未知。保留归档观测时间为 2026-09-25 的原记录，没有改成这次 HTTP 的时间。

本轮累计角色详情 GET 两次：第一次发现问题，第二次用于实际修复验收。内部上游请求数未直接测量，不将一次本地 GET 说成一次上游请求。最初核验脚本也遗漏解包；另一次全局最新归档结构样本属于其他角色，已明确纠正，最终结论只依据同一目标角色的实时/适配比较。未保存完整私人响应或真实属性值。

## 异环：重新登录后的真实字段

第一次只请求角色接口一次，得到 `401 / auth_expired`，未续期、重试或覆盖旧快照。用户在预览中重新登录并明确告知完成后，第二次独立角色请求 **HTTP 200、业务码 0，原始及标准化均为 21 个角色**。

- 觉醒、技能、弧盘及套装实际字段存在并可解析；装备共 125 件（core 17、pie 108）。
- 504 项角色属性、233 项装备主属性、500 项副属性的 ID 保留；主属性有 1 项原本缺名称和值，标准化后仍未知。
- 125 件来源均未提供品质、面积与列表完整性依据，这些输入仍未知，不能据此次成功读取宣称自动评分依据齐全。

两次异环核验各只发生一次上游请求，均无自动续期或重试。成功核验不改写业务缓存、模型或权重；原始响应不落盘，仅保留字段存在性、类型、数量和匹配布尔值。

## QQ：朋友群实际收图

用户先指定朋友群、允许使用现有机器人，再明确允许一次临时测试窗口。测试仅发送已展示的公开鸣潮日历第 1/3 页，不含私人账号资料。图片由隔离分支实际 Vue/Chromium 渲染生成，1080×1052、153167 字节，保留陈旧来源与未知日期提示。

现有平台不再支持主动推送，群聊被动回复须关联新入站消息；因此没有主动发送或重放历史回复。[腾讯官方发送消息文档](https://raw.githubusercontent.com/tencent-connect/bot-docs/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)

测试脚本先通过 13 项离线验证及只读预检，确认唯一朋友群、现有 SDK/发送契约与图片。经用户窗口授权，先设置独立恢复保护，暂停原 QQ 网关，确认原进程停止后才启动临时单网关。用户在 READY 后发送唯一新指令；上传使用 `srv_send_msg=false`，关联该消息以 `msg_seq=1` 只回复一次。没有启动第二个并行网关，没有改正式 unit、配置、群范围或 BotState。

最终证据：**平台返回发送回执；用户回复“显示正常”；临时网关结束，原机器人恢复，新的连接就绪标记已验证；受保护的 QQ 配置、源码与原状态库校验一致。** 测试窗口内一次控制端 SSH 状态查询失败，未重跑执行或补发；随后只读状态确认 `restored / receipt_returned=true / original_files_unchanged=true / gateway_ready_verified=true`。

本次证明修复后本地公开日历图经过实际 QQ 上传、回复和客户端显示正常；不扩大为整批代码已部署、全部图片页或全部私人指令均通过。线上原 API、数据库及产品代码未替换。经授权的临时脚本/单元仅位于 `/run`，无常驻辅助网关，恢复保护已解除。
