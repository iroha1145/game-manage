# 前端布局与动效

保持 PR #8 首次提交的页面结构与紧凑信息排布。2026-10-17 起，表面与文字按下面「表面与文字」一节的规则统一：中性灰、扁平表面、四档圆角、12px 起的字号阶梯和以 400、500 为主的字重。深色主题沿用同一套层次。

游戏主题色沿用 `GAME_STYLE` 与日夜主题变量。选中态、焦点环、进度条和详情标题使用当前游戏的颜色；正文保持中性色和稳定的可读性。

## 表面与文字

规则来自对参考站的实测（见文末「2026-10-17 参考」），以及《Don't Make Me Think》和《写给大家看的设计书》的亲密、对齐、重复、对比四条原则。

- **灰色**：两套主题的灰都不带色相。小字在任何底色上对比度不低于 4.5:1。游戏色和图表色（`--game-*`、`--chart-*`）不跟着改。
- **表面**：静止的东西不加阴影，包括卡片、按钮、导航选中项、品牌标和侧栏。只有菜单、弹窗、提示和分段控件的选中块保留阴影。卡片是一层底色加一圈细线；卡片里面的分组用一层底色台阶或间距，不再套带边框的框。没有纸面点阵，顶栏不做毛玻璃。阴影变量（`--card-shadow`、`--btn-shadow` 等）保留名字、值为 `none`，其他分支引用它们时也会变平。
- **圆角**：`--radius-card` 14px（卡片、弹窗），`--radius-well` 10px（内层面板、分段控件轨道），`--radius-control` 8px（按钮、输入框、小块），`--radius-chip` 6px（标签、徽章）。药丸、圆点、进度条用 999px。
- **字号**：12px 是下限，用于元信息和标签；正文与列表 13～14px；卡片标题 15～16px；页面标题 24px；关键数字 20～28px。只有日历日期格里的「今天」等极窄位置可以用 11px。
- **字重**：正文 400，标题、标签和选中项 500，600 只给页面标题和大数字。苹方 600 以上都会落到「中粗」，大面积使用会显得重。
- **小标签**：不用大写加字距的英文小标题、编号（01、POOL 01）和补零计数。带信息的标签（游戏 / 分类、元素 · 定位）改为正常大小写的 12px。等宽字体只给真正的代码。

## 文案

按「删掉一半的字，再删掉剩下的一半」处理说明性文字，只保留界面本身看不出来的信息：数据状态与陈旧提示、数据来源、估算口径、时区（每页一次，写「北京时间」）、不可撤销操作的后果、输入凭据处必要的一句安全说明、出错后下一步怎么办。页头不再配复述标题的说明句，正常状态不写安抚话，导航名与页面标题一致。机器人图片里作为唯一标题的文字（例如日历图的「版本活动时间轴」、公告图的摘要说明）按图片模式保留。

## 交互约定

- **导航与标签**：背景指示器位于独立层级，文字和图标始终在其上方。左侧菜单的选中项是一块浅色底，不加投影；侧栏和内容区之间只用一条细线。窄屏标签条在选择变化或容器变窄时，将被遮住的选中项滚入视野；不滚动整个页面，也不打断用户手动浏览标签。
- **详情面板**：保留鸣潮与异环原有的居中弹窗、各自的尺寸与样式，手机上也保留四周留白。两者仅共用模态生命周期与动效逻辑。打开约 250ms，关闭约 150ms，位移 8px；关闭动画结束后才移除弹窗、解锁滚动并恢复入口焦点。动画事件缺失时，220ms 后仍会完成关闭；组件提前卸载会取消等待。
- **总览卡片**：保留原来的紧凑排版，数字和说明并列，账号与更新时间同一行。进度条平滑更新。悬停时边线染上游戏色并有一层跟随指针的浅色高光，卡片不上浮、不加阴影；高光不覆盖文字。
- **活动日历**：保留原有紧凑时间轴，每条活动 32px 高，名称、分类、状态和剩余天数在同一行；使用游戏主题色带、斜纹背景和已过时间填充。今天使用圆形标记，日期头分三行对齐。时间轴占满可用高度，较多活动时滚动，游戏名称与日期头保持固定。日期比例、单日标记与裁剪区间仍使用原有数据语义。关闭详情或按 Escape 后，焦点回到原活动；详情滚动遵守减少动态效果偏好。
- **减少动态效果**：系统开启 `prefers-reduced-motion` 后，关闭动效、标签平滑滚动和指针跟随，弹窗直接关闭。功能和当前选中状态保持可用。
- **动画范围**：数值和页面内容无需等待动画完成才能阅读。动效绑定到用户操作或内容变化，卸载时清理观察器、事件和待执行帧。

## 参考与取舍

这一轮先用无头浏览器量了参考站的字体、字重、字号、灰色、边框、圆角、阴影和动效参数，再对照改动。没有复制参考站的组件或引入新的运行时库。

| 来源 | 学到并落地的部分 |
| --- | --- |
| [ObsidianUI](https://www.obsidianui.dev/components) | 中性灰三档、400 与 500 两种字重为主；样式表里直接用 transitions.dev 的动效变量。 |
| [beautifului.dev](https://www.beautifului.dev/) | 高密度界面也可以不重：字号范围窄、字重克制、线条极淡。 |
| [beUI](https://beui.dev/) | 用一层色阶区分表面，而不是阴影；标题与正文字号差拉开。 |
| [transitions.dev](https://transitions.dev/) | 动效变量本来就是这一套；这次把下拉菜单、提示气泡和卡片高光的时长与缩放换成对应用途的变量。 |
| [feel](https://diip3sh.github.io/feel/) | 按压反馈以底色变化为主、幅度小；保留现有 0.97～0.98 的按压缩放。 |
| [tasteskill.dev](https://www.tasteskill.dev/) | 只取适用于应用界面的去噪规则：不用编号小标题、大写小标签、装饰等宽字、静止阴影和毛玻璃。它针对营销页的「不画细线」「必须有大图」不适用，表格和列表的分隔线保留。 |
| [rareui.com](https://rareui.com/) | 站点的防机器人检查拒绝了无头浏览器，没有测量，也没有采用。 |

## 验证

在 `frontend` 运行 `npm test` 和 `npm run build`。持续集成用 Node 22，本机若是更新的 Node，要另用 Node 22 跑一遍测试。DOM 回归覆盖动态 class 更新后的导航层级、快速切换、横向滚动、减少动态效果、弹窗关闭与卸载清理。现有详情测试继续验证按需挂载、关闭和账号切换。

浏览器使用模拟快照检查桌面及手机布局、日夜主题、原生模态状态、Escape、焦点恢复和横向溢出；它验证界面行为，不依赖私人游戏账号。
