# 前端布局与动效

2026-10-17 第三轮按用户给的设计稿 game-manage-ui-v1 重做界面：暖白的纸色画布上放白色卡片，一个蓝色强调色，每个游戏一种浅色底，平面、细线、少阴影。功能、数据含义和文案规则不变，变的是视觉层和几处排版。第二轮里的图表、横向滑动、滚动出现、视差和头像行保留下来，换成这套外观；毛玻璃外壳、深色主视觉、鲜艳渐变、胶囊按钮和指针高光去掉。深色主题是从同一组颜色单独调出来的，不是把浅色反过来。

## 表面

- **画布与卡片**：浅色主题画布 `--bg #f7f6f3`，卡片纯白 `--card-bg`，一圈细线 `--card-border #eceae5`，阴影 `--card-shadow` 几乎看不出来。卡片里的小块用 `--surface-soft` / `--panel-bg`，轨道和分段控件用 `--control-track #f1f0ec`，分隔用 `--border`。
- **浅色底是唯一的大块填色**：每个游戏一种浅色底 `--game-*-tone`（终末地天蓝、鸣潮沙色、异环珊瑚、英雄联盟青绿）。总览主卡、活动卡、游戏页顶部横幅、日历详情的抬头都用它；上面的小字用该游戏的墨色，标题用正文色，不在浅色底上放白字。
- **毛玻璃**：只留给浮在内容上方的东西：侧栏（白 85%、模糊 16px）、手机底部导航，以及异环队伍照片上的两个角标。卡片、顶栏、下拉菜单、弹窗都是实色。
- **圆角**：外壳 28px（`--radius-shell`）、卡片 24px（`--radius-card`）、卡片内的小块 16px 或 14px（`--radius-tile`、`--radius-well`）、按钮和输入框 12px（`--radius-control`）、标签 6px（`--radius-chip`）。胶囊形只留给本来就是圆的东西（圆点、圆环）。
- **阴影**：静止的卡片只有 `0 2px 8px` 的一层极淡阴影；下拉菜单、弹窗、侧边栏弹窗用 `--popover-shadow`。没有彩色光晕。

## 颜色

- **一个强调色**：`--accent #4263b6`，悬停 `#344f94`，浅底 `--accent-soft #e9edf7`。主按钮、选中的导航项、链接都用它。游戏页根元素带 `.game-theme`，把强调色换成该游戏的墨色、浅底换成该游戏的浅色底。
- **每个游戏四种颜色**：`--game-wuwa` 等是墨色，能当文字用（在白底和自己的浅色底上都不低于 4.5:1）；`--game-wuwa-tone` 是浅色底；`--game-wuwa-vivid` 是线条色，用于进度条、计量条和只有一个系列的图表（对白底不低于 3:1）；`--game-wuwa-2` 是多个游戏同在一张图里时该游戏占的颜色。`gameVars(id)` 给出 `--game-accent`、`--game-tone`、`--game-vivid`、`--game-vivid-2`。
- **校验过的颜色**：设计稿里的灰字 `#74777e` 在画布上只有 4.15:1，改成 `--text-muted #62656c`（5.40:1）和 `--text-faint #666970`（5.09:1）；沙色和珊瑚色的墨色也加深到 4.5:1 以上。图表色 `--chart-1` 到 `--chart-8` 按固定顺序取用，浅色和深色主题各自用 dataviz 的校验脚本检查过；四个游戏同框时的颜色（浅色 `#3363b8 #dcab4b #cf5f88 #00704f`，深色 `#3987e5 #c98500 #d55181 #008300`）两两都检查过色盲可分辨度。
- **状态色**：成功、警告、失败只表示状态，总配文字说明，不拿来当系列颜色。

## 文字

- 拉丁字母和数字用 Geist（随前端打包，SIL 开放字体许可，见 `THIRD_PARTY_NOTICES.md`），中文落到苹方、微软雅黑等系统字体。机器人图片仍用自己的渲染字体。
- 页面标题 28px/600，区块标题 18px/600，卡片标题 16px/600，正文 14px，说明与标签 12px（下限）。标题和强调用 600。
- 关键数字 28～44px、字重 500～550、字距 -0.03 到 -0.06em，等宽数字，单位缩小跟在后面。

## 布局

- **外壳**：侧栏离窗口边缘 16px，210px 宽（1250px 以下 192px），顶部是四块小方格旋转 9° 的标志和「游戏管家」。顶栏不再浮动吸顶，是页面最上面的一行：左边搜索框（⌘K / Ctrl K），右边日期（本地版带时钟）、主题切换，云端多一个「退出登录」。页面名只在页面里作为大标题出现一次。
- **手机**（720px 以下）：侧栏变成抽屉；底部是一条导航（总览、日历、账号、游戏与菜单），最后一项打开抽屉，关闭后焦点回到它。
- **搜索**：⌘K 打开的跳转搜索，只在本机已有的数据里找页面、游戏、游戏页的栏目、进行中的活动和已知角色，选中后跳过去，不发任何请求。游戏页地址支持 `?tab=`，搜索结果可以直接打开某个栏目；栏目名单在 `search-index.js`，测试会核对它和各游戏页的标签是否一致。
- **总览**：标题下一行写今天的计数。第一行左边是主卡：一个游戏的浅色底，写它的主要数字（体力、距上次 6★ 或胜率）、回满时间、账号和「打开」按钮，右边是该游戏等级最高的几张角色头像，下面一排游戏名可以切换；右边是「日常进度」：圆环写完成了几项，列出鸣潮的活跃度和周期进度、异环的日常活跃和周本剩余、终末地的每日与每周任务（只读，数据来自已有快照）。往下是游戏状态卡（横向滑动，带进度条、头像行和直达栏目的链接）、活动截止图（7 天 / 30 天）和最近截止的一项、抽卡概况（终末地寻访记录或异环社区抽卡统计）、近期活动卡（各自的浅色底）和公告与资讯。
- **游戏页**：顶部横幅是该游戏的浅色底，白框、英文名、游戏标志斜放在右下角；下面是标签页，标签页里用白色卡片组合，每页只有一两块浅色底的重点卡。角色、干员、战队和选手用设计稿的角色卡（白框里一块浅色底的图区，等级是左下角的白色小标签）；机器人图片里换成横向的紧凑卡，保持图片高度。详情弹窗改成右侧侧边栏，宽度按内容定（鸣潮 560～960px、异环 720px）；终末地的干员配装和英雄联盟的对局详情仍在页内展开，因为测试固定了它们的焦点和滚动位置。胜负、品质、奖牌这类有含义的颜色保留，并都配文字。
- **活动日历**：左边时间轴，右边一栏：没选中时是「即将截止」列表，点一项就换成它的详情（抬头是该游戏的浅色底），再下面是计数和各游戏占比。1250px 以下右栏移到下方。
- **横向滑动**：`HRail.vue`，吸附滚动、边缘渐隐。有标题行时左右箭头放在标题行右侧（设计稿的做法），否则浮在两端；只在内容超出时出现。机器人图片里改为换行排开。

## 图表

图表是手写的 SVG 或 CSS 组件，没有引入图表库。规则来自 dataviz：

| 组件 | 用途 | 要点 |
| --- | --- | --- |
| `RingGauge.vue` | 体力、进度、胜率、完成数 | 圆角端点，`role="meter"` 带数值；数值未知时只画轨道 |
| `BarChart.vue` | 每天、每期、每类的数量 | 柱宽不超过 24px，只在数据端圆角；只给最高的和强调的那根标数字，其余在悬停或聚焦时显示，可附一句说明（比如哪些游戏）；30 天这类长轴每隔几天标一次刻度，读屏仍读出每一天 |
| `TrendChart.vue` | 随时间变化的数值 | 2px 平滑曲线和渐变面积，末端圆点加数值，悬停或方向键移动十字线 |
| `DonutChart.vue` | 占比（不超过 6 份） | 份与份之间留 2px 缝；两份以上一定有图例，图例写数值和百分比 |

每个图表的数值不靠悬停也能读到：直接标签、图例，或者给读屏器的列表。图形的颜色从不用在文字上。

## 图片

- 仓库不带任何官方美术资源，也不新增图片来源。主卡、头像行和角色卡用数据里已有的角色图标地址；没有图片时用该游戏的标志方块作为兜底，样子按设计稿的 `.role-art` 做成有意为之的样式。
- 第二轮的原创几何主视觉 `GameArt.vue` 已删除。

## 动效

- **滚动出现**（`v-reveal`）：默认可见。只有页面首屏以下、浏览器支持 IntersectionObserver、没有开启减少动态效果、也不在机器人图片里的元素，才先藏起来等滚到再出现。
- **视差**（`v-parallax`）：只用在装饰图层上（总览主卡的头像、游戏页横幅的标志），按 `--plx-range` 轻微位移，文字和按钮不动。
- **其他**：数字变化时轻微上浮（`v-pop`），标签页和分段控件的滑块（`v-glide`），切换后的内容淡入（`.t-panel`），主题切换的圆形展开。按下时下沉 1px，悬停只换底色，不再上浮加光晕。
- **侧边栏弹窗**：详情类弹窗加 `.sheet-dialog`，贴着窗口右侧、占满高度，从右边滑入（`.t-dialog` 的动画读 `--dialog-shift-x`）。关闭动画结束后才移除弹窗、解锁滚动并恢复入口焦点。
- **减少动态效果**：系统开启后，全局关闭动画和过渡，滚动出现和视差都不启用。
- **机器人图片**：`render.css` 让滚动出现的元素直接可见，取消视差位移、毛玻璃和横滑，图片里的内容不依赖悬停、滚动或动画。

## 文案

只保留界面本身看不出来的信息：数据状态与陈旧提示、数据来源、估算口径、时区（每页一次，写「北京时间」）、不可撤销操作的后果、输入凭据处必要的一句安全说明、出错后下一步怎么办。页头不配复述标题的说明句，导航名、链接名和页面标题用同一个词（比如游戏卡上的直达链接就用该栏目的标签名）。测试里写明要保留的说明句（海克斯的样本胜率、终末地挑战记录的完整性、连接森空岛的提示、机器人公告图的摘要说明、机器人日历图的标题、QQ 群的管理范围、已有授权保留）不删。

## 参考与取舍

### 2026-10-17 第三轮：设计稿 game-manage-ui-v1

以用户给的设计稿为主：颜色、圆角、卡片、按钮、侧栏、搜索框、主卡、日常进度、游戏卡、趋势卡、抽卡卡片、活动卡、日历右栏、侧边栏弹窗和手机底部导航都按它来。和设计稿不同的地方：

- 设计稿的灰字和两种墨色对比度不够，按上面的数值加深。
- 设计稿用的是演示数据。这里每张卡片只读真实快照：「今日任务」改成只读的「日常进度」（没有能勾选却不保存的复选框），「体力使用率」趋势换成活动截止图（没有体力的历史数据），抽卡概况只在有寻访记录的游戏出现；设计稿里的收藏和提醒没有对应功能，没有加。
- 设计稿的角色立绘是图片素材，这里只用数据里已有的角色图标。

再按两本书检查一遍：

- 《Don't Make Me Think》（Krug）：能点的东西看起来就能点（按钮有边框，链接是强调色）；每个区域一个主要操作；同一个地方在导航、链接和标题里叫同一个名字；去掉不帮助理解的字和装饰（页脚的时区说明删掉，图表说明里已经写了）；每张卡片最先看到的是它的主要数字。
- 《写给大家看的设计书》（Williams）：亲密（相关的数字放在一组，组与组之间靠留白分开，不套框中框）；对齐（每张卡片一条左边线和基线）；重复（同一类内容在各个标签页里用同一种卡片结构）；对比（不同就做得明显不同：字号、字重、浅色底，而不是五种接近的灰）。

## 验证

在 `frontend` 运行 `npm test` 和 `npm run build`。持续集成用 Node 22，本机若是更新的 Node，要另用 Node 22（`/usr/local/bin/node --test src/*.test.js src/components/*.test.js`）跑一遍。DOM 回归覆盖导航层级、横向滚动、滚动出现（只隐藏首屏以下的卡片，机器人图片和减少动态效果下不隐藏）、视差、横滑箭头、弹窗关闭与卸载清理、搜索栏目名单和总览各卡片的数据整理。机器人图片的真实渲染测试需要先用 `scripts/cloud/build_frontend.py --frontend frontend` 构建，再设置 `QQ_RENDER_TEST_EXECUTABLE` 和 `QQ_RENDER_TEST_FONT` 运行。

浏览器检查覆盖桌面、平板和手机宽度、日夜主题、搜索、侧边栏弹窗、抽屉、Escape、焦点恢复和横向溢出；它验证界面行为，不依赖私人游戏账号。
