# 云端看板与 QQ v3 实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development to implement tasks. 用户指定 gpt-6.1-sol high 子代理实施，root 只做必要审查验收，不重复无意义复验。

**Goal:** 交付已批准的一步绑定、三类活动、完整抽卡/总览/帮助长图，以及网站与本地的功能视觉一致性。
**Architecture:** 保留本人账号查询和受限公共素材管线；扩展版本化显示文档与渲染器；网站复用本地组件，在云端运输/身份边界适配。
**Tech Stack:** Python/FastAPI/SQLite/Pillow，Vue/Vite/node:test，既有独立 Linux services。
**Spec:** ../specs/2026-10-14-cloud-qq-v3-design.md

## 全局约束与工作区

- 用户“可以，开始吧”授权本设计实施与既有独立服务发布流程，不另为可逆的同范围步骤重复请求授权。
- 复用现有隔离 worktree `C:/Zcode/game-manage-cloud-qq`；主仓 `C:/Zcode/game-manage` 只读。
- 不动 LOLhelper/Caddy，不读/输出秘密，不主动发 QQ、不 push/merge。真实注册、游戏登录、验证码和真人指令仍由本人操作。
- 保留当前两个群、有效绑定、游戏授权、网站会话、状态库和独立密钥；迁移前备份、失败回退。
- 用户最新需求取代旧帮助、分页和回执往返设计，原游戏身份隔离不放宽。
- 缺失数据不补零、未知日期不造时分、不引入自定义评分；官方既有抽卡配色保留来源。
- 子代理仅提交自己负责文件；共享文件修改前协调，不清理其他人的改动。

## 审查重点

1. 绑定码消费/关联创建/失败限频/持久幂等/旧迁移兼容；不得因简化流程造成身份覆盖。
2. 聚合只选本人游戏、渲染后授权复核、公共前缀命令与私人聚合边界。
3. 日期精度、168小时窗口、版本维护边界、来源陈旧、空列表与无快照。
4. 长图字号/字数/像素/编码预算，图标来源与安全；禁止静默截断。
5. 云端写操作按精确本人路由放行，不能为恢复界面放开本地管理/全局接口。
