# 云端看板一致性与 QQ 交互 v3 需求设计

状态：2026-10-14 用户回复“可以，开始吧”，批准本设计并授权实施。用户新需求覆盖旧方案中同义的活动/日历指令、往返回执绑定及简化卡片设计。当前朋友验收结果继续保留，不宣称第二名真人隔离或终末地私人数据已通过。

## 1. 已确认目标

- 用户确认绑定方式：网站生成一次性绑定码，QQ 发送一次即完成，不再把机器人回执填回网站。
- 用户确认总览改版只作用于 QQ；网站严格恢复本地看板的既有界面和功能，不按本次截图另做网站总览。
- QQ 未绑定提示采用清晰、简短的逐步引导；一个步骤只讲当前需要做的事。
- QQ 新增独立的「近期活动」「活动」「日历」；无游戏前缀时聚合本人已绑定且有可用数据的游戏，有前缀时只返回对应游戏。
- 抽卡查询尽可能覆盖本地对应弹窗的信息，各卡池依既有顺序排列成一张长图，保留原本配色及图表含义。
- QQ 总览逐游戏展示实际可得的体力、活跃、收集、角色、装备等速览，未知不填零；帮助按功能分类、每格一个功能及一条主指令。
- QQ 图片整体提高字号、信息层级和图标覆盖，避免窄格反复换行；不新增自定义评分、评级、排名或伤害估算。
- 网站保留云端必要新增项：网站身份、用户隔离、会话、QQ 绑定和公共采集管理权限。
- 开发沿用 gpt-6.1-sol high 子代理，root 做必要审查、针对性验收；不反复执行没有新增价值的检查。

## 3. 一次完成绑定与引导

### 3.1 用户流程

1. 未绑定的私人查询返回独立绑定提示，而非整张帮助图：提示登录看板，在「QQ绑定」生成一次性码，再在本群发送「绑定 实际绑定码」。没有网站身份时先说明邀请注册入口。
2. 网站生成码后只显示一条可复制的绑定指令、到期时间和使用说明，不显示多余回执表单。
3. QQ 收到有效指令后完成绑定，回复「绑定成功」，再提示「我的总览」或对应游戏查询。到此结束，不要求返回网站。
4. 失败按真实原因给下一步：码无效/过期、已使用、请求过频、当前 QQ 已关联其他网站账号、网站账号不可用。不要输出数据库异常或秘密。
5. 引导只在用户发指令时被动回复，不主动群发，不索取网站密码、短信码或游戏令牌。

### 3.2 服务契约

- 在同一数据库事务中检查网站身份、码有效性与冲突，原子消费一次性码并创建关联；两条并发兑换只能成功一条。
- 建议码有效期缩短至 2 分钟；同一网站用户只保留一个活跃码，生成新码撤销旧未消费码，不影响已经建立的关联。
- 保留速率限制、现有允许群、发送幂等和关联撤销；失败事务不得意外消费码或覆盖其他用户的关联。
- 失败限频计费不能随兑换业务事务回滚；成功提交但回复丢失时，同一可信消息重放可查回原结果，不再次创建关联。数据库版本迁移保留既有 confirmed links，不在旧迁移文件中就地改表。
- 对同一身份已绑定同一网站用户给幂等成功或明确「已绑定」；冲突绑定不能静默转移。
- 旧待确认请求不得自动升级为新绑定；切换时明确失效旧待办，已确认关联保留。旧 API/界面/帮助统一迁移，不能仅删除前端确认按钮。
- 短时码是授权凭证。公开群里发送仍存在被其他成员抢先兑换的可能，短期、单次和限频只能缩小风险；不把该方式描述为额外的 QQ 实名证明。网站生成处明确提醒只在认可的群内使用、不要提前分享绑定码。
- 跨群统一关联保留为同批身份专题：先核实平台标识语义与已有关联冲突，再决定迁移；不能直接删除 group_openid 条件。群允许范围与用户绑定仍分别管理。
- 不依赖尚未开放的 QQ 消息外链权限；网站入口可在帮助中说明由管理员提供，禁止把游戏凭据作为绑定材料。

## 4. 活动指令与时间契约

| 指令 | 返回内容 | 呈现 |
| --- | --- | --- |
| 近期活动 / 鸣潮 近期活动等 | 从当前时刻起 7 天内已确认将结束的活动，以及 7 天内将开始的活动 | 「即将结束」「即将开始」两区；区内按游戏、相关时间排序；名称、类别、日期时间、剩余时间、渠道来源 |
| 活动 / 异环 活动等 | 当前已确认正在开展的活动 | 按游戏分区的完整列表，含类别、结束时间/时间边界、来源；不混入尚未开始或已经结束的活动 |
| 日历 / 终末地 日历等 | 活动在日期轴上的分布 | 同一日期轴、按游戏及活动类别分区、横向活动条、当日线、起止日期、图标/可用封面，纵向长图 |

- 「活动」与「日历」不再指向同一命令枚举；保留原有游戏别名，但帮助和兼容别名统一解释新语义。
- 无前缀：先确认 QQ→网站关联，读取本人有效授权对应游戏集合；一个游戏多个账号去重，只读该游戏公共活动快照，不合并私人账号载荷。
- 有前缀：只查询对应游戏；沿用现有单游戏公共活动无需私人游戏授权的能力。无前缀且尚未绑定时，引导绑定，也可提示使用带游戏名前缀的公共查询。
- 可用数据包含明确标注陈旧的最后成功快照；某个已绑定游戏没有快照或失败时给出简短状态，不能悄悄当成没有活动。其他游戏正常返回。
- 统一北京时间；7 天默认连续 168 小时，边界测试固定 now。开始/结束是独立条件，不能依赖标题关键词推断时间。
- 仅日期、更新后、版本结束前、条件解锁等时间保留原始精度。不能给相对时间伪造时分、精确倒计时或实线区间；时间待确认项单列，不能混进「已确认」结果。
- 已有确切维护公告支撑的「维护前」截止可纳入已确认结束项，保留来源与边界语义；不能仅因 end_precision 不是 minute 就丢弃。活动多阶段分别画条，不能连接中间未开放区间。成功空列表与未采集分开显示。
- 剩余时间按真实时刻计算并显示到天/小时/分钟，不显示秒；以小时/分钟呈现不足一天的项目。
- 日历默认建议采用当前自然月的共同日期轴；跨月条截断处用延续标记，并保留真实日期文字。单游戏版本完整起止已确认时可显示版本名称，但不凭截图假定所有游戏有相同版本周期。窗口策略属于设计建议，尚未实现。
- 来源展示采用实际贡献内容的官网/社区/官方 B站渠道标识、文章标题或可验证出处；来源不可用时保留状态。未批准外链时不向 QQ 自动发送可点击链接。
- 每个视图使用统一去重和筛选规则。网页已有规则可复用或移成共享数据契约，不能把某次抓取非空当作全量覆盖。

- 「异环 抽卡」以本地 `NteGachaPanel.vue` / `NteCommunityGacha.vue` 对应弹窗为基准，逐卡池展开，保留来源顺序、总抽数、来源提供的统计、出货条目、角色/武器图标、获取时间、抽数横条及原有颜色图例。
- 核查已确认：本地与云端的社区统计组件已复用；本次重点是 QQ 投影丢失信息，以及云端可选逐抽账本入口尚未等价。不要重复重写已经一致的组件。
- 塔吉多 `lucky_type` 的颜色/评价属于上游现有展示策略，若保留必须标明来源；不另造本项目评分。横条表示该次出货抽数，不能误作当前保底进度。
- 对齐当前本地映射：条目 lucky_type 1/2 为绿、0/3 为黄、4 为红、未知为灰；0 不展示评价文字。深色条色为 #04c8a3 / #edbc49 / #e55961，浅色对应 #8fdcc7 / #f3cf73 / #f2a1a7。顶部 luck_type 1–5/6–10/11–15 对应绿/黄/红。缺 guarantee 不画比例。
- 社区统计窗口与本人逐抽账本分区，账本缺失则明确「未导入」，不从社区统计推导完整历史或当前垫抽。
- 鸣潮与终末地分别复用本地各自抽卡规则和数据字段，不套异环的卡池规则；终末地仍区分鹰角寻访与森空岛身份。
- 正常数据生成一张长图；长图超过实际平台/资源限额时明确降级或限制，并说明未展示范围，不能无提示截断。首先通过合理字号、行高和编码压缩实现长图，而非缩小到不可读。

## 6. QQ 总览、帮助及统一视觉

### 6.1 QQ 总览

- 每游戏一块：紧凑账号/角色标题、体力与日常重点指标、收集及进度统计、代表性角色与已知装备行、来源时间/状态。
- 鸣潮可展示真实已有的联觉/索拉等级、活跃、成就、数据坞、探索/收集、共鸣者与已采集武器/声骸；异环展示战斗/都市体力、活跃、鉴别等级、成就与卡带、角色/弧盘/已知装备；终末地按可得档案字段适配。
- 总览提供速览，完整角色和装备仍使用各自详情指令。装备只表示已采集配装，不宣称完整背包库存。
- 布局参考截图的主指标大字、次要指标网格、角色装备横行；采用本项目已建立的主题、字体与游戏主题色，不把缺失字段填零或挤入过窄小格。

### 6.2 帮助

- 按「绑定与账号」「总览与角色」「资源与进度」「抽卡」「公告与活动」等分区，只列本项目实际可用功能。
- 每格首行功能名、次行一条主指令，字体大小/颜色区分；别名放页脚或单游戏帮助说明，不把多项功能拼在一个格内。
- 通用帮助说明游戏前缀语法，单游戏帮助列实际指令示例；未支持能力不作为可点击/可用指令展示。

### 6.3 图片共同验收

- 以手机实际查看为验收基准。建议 1080–1200 像素逻辑画布，正文约 26–30 像素、次要文字不小于约 22 像素，最终按真实设备与平台文件预算调校，不承诺未实测参数。
- 统计格、帮助格、角色行、抽卡条、日历条分别布局，不再用一种窄网格渲染所有内容；值与日期优先保持整行，长名称使用宽行/合理换行而非缩成小字。
- 图标优先复用本地映射和可核验官方素材；缺图使用明确的统一类别占位，避免错配他人角色/武器图。终末地未核实素材不猜 URL。
- 保留账号隔离的渲染缓存键与授权重验；活动倒计时/日期窗口须参与缓存新鲜度，不能长期复用旧剩余时间。

## 7. 云端网页与本地一致性

优先复用本地现有 Vue 组件、布局、字体、主题、响应式、模块顺序、弹窗及操作入口，在运输层适配本人账号作用域；禁止用来源字段树替代已有完整面板并称为一致。

| 范围 | 核查/修复方向 | 合理差异或边界 |
| --- | --- | --- |
| 应用壳、导航、首页、手机布局 | 恢复本地导航、游戏页、页签及收纳行为；网站总览继续以本地为准 | 增加网站登录/退出/会话入口 |
| 鸣潮各分区、角色/攻略/抽卡/成长历史 | 已复用部分保留；逐项补齐隐藏操作及本人范围接口接线 | 管理员采集、审核与普通查询分权 |
| 异环分区、角色/资产/抽卡/攻略 | 社区抽卡组件已复用；恢复账本读写入口及本地弹窗；资产传入角色映射 | 收藏/偏好按网站用户、账号及角色隔离 |
| 终末地档案/寻访/挑战/图鉴/地图/蓝图 | 完整对照组件、字段、分页、导出与已有本人 CRUD；区别未接接口与真正缺数据 | 两授权身份不自动合并，无真实账号部分仍待验 |
| 公告、活动、日历与刷新状态 | 保留既有来源策略/主题/状态及有效入口，校验同数据下视觉和筛选一致 | 公共来源维护仅管理员操作 |
| 桌面专用能力 | 单列本地依赖及处置，不暗中伪造云端支持 | LCU、本机窗口/截图/OCR、文件路径不能直接在云端执行；需本地代理或保留明确入口说明 |

每模块交付必须包含「本地原行为→云端对应行为→数据来源→差异原因→处置→验证状态」。真正无法一致的部分列出原因及建议，不用「云端模式」笼统解释。

本轮已定位的具体接线缺口：CloudGameCard 没有向 NteAssetsPanel 传 roles，房产入住角色名称及搜索可能退化；NteRolesPanel 收藏作用域仅账号，需要补用户/账号/角色；模块顺序需按本地页签排序；本地 hash 路由、手机抽屉与焦点行为尚未恢复。private_routes 已有异环账本预览/导入/规则/导出、鸣潮抽卡导入、蓝图 CRUD/导出，优先接现有本人范围接口，不重建平行后端。攻略和终末地地图服务未挂载则作为明确后端缺口处理。

主要实现位置：QQ 的 commands.py / bindings.py / query_routes.py / presentation.py / cards.py / card_rendering.py / rendering.py；新增独立活动视图规范模块以减少大文件耦合。网站主要为 CloudApp.vue / CloudGameCard.vue / http-client.js / accounts-api.js，以及与本地对应的游戏组件和 private_routes.py。身份迁移与旧确认入口退役单独成批，不能混在视觉改动里隐式上线。

## 8. 建议分批顺序与验收门槛

1. 绑定原子兑换与精简引导，先验证新旧关联保留、冲突、并发及撤销；一次真实用户绑定验收。
2. 活动三类命令及授权游戏范围、日期精度和来源契约；复用一组固定时间样本对照网站与 QQ。
3. QQ 视觉公共组件、帮助、总览、抽卡和时间轴日历长图；先交合成脱敏预览，再做每种版型一次必要视觉审查。
4. 网站按模块恢复本地一致性，分别验证桌面/手机关键流程；已有一致模块不重写。
5. 最终只运行受影响范围回归及必要集成测试；分批发布独立 game-manage，保留回退；真实 QQ 消息由用户发送。

最低测试覆盖：同码并发/过期/重放/冲突/旧关联；未绑定与无可用游戏；多账号去重/撤销；7天边界/跨月/时区/日期未知/陈旧来源；全卡池顺序/色彩/缺失图标/历史不完整；手机字号与长名称；刷新状态、用户切换和两用户数据隔离。

不修改、重启或迁移 LOLhelper，不调整其 Caddy 站点；不输出凭据或私人载荷；不 push/merge。公网与 QQ 平台能力、终末地实测、图片大小均以实际验证为准。

## 9. 待确认与待验证

- 已批准默认值：一次性码 2 分钟、日历默认当前自然月、单游戏公共活动保持无需绑定。
- 平台待核实：跨群统一用户标识、外链能力、较大长图文件预算；先用现有能力，不为排版随意扩大限制。
- 数据待核实：活动横幅及部分终末地图标；各游戏真实字段覆盖和缺失详情；日期/版本边界无法确认时明确标注。
- 真人待验：第二名朋友独立授权及隔离、终末地私人数据、改版后真实送图与一步绑定。当前旧版总览验收不能替代新流程验收。
